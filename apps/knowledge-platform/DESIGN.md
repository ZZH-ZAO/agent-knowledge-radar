# Knowledge Platform Design（知识平台设计规范）

> 来源依据：`.claude/docs/user/awesome-design-md/analysis.md` 与 `docs/patterns/前端设计控制/frontend-design-control-patterns.md`。  
> 目标：让后续 Agent 修改前端时，持续保持一个中文知识工作台的稳定气质。

## 1. Product Intent（产品气质）

这是一个给个人长期学习、项目沉淀、方案抽象和面试训练使用的知识工作台。

界面应该像专业知识库和工程控制台，而不是营销落地页：

- 信息密度适中偏高。
- 页面结构清楚，适合反复查阅。
- 视觉克制、稳定、有层级。
- 中文内容优先，项目名和专业名词可保留英文。

## 2. Layout（布局）

- 使用左侧固定导航 + 右侧工作区。
- 主工作区优先使用两栏：左侧列表，右侧详情。
- 顶部只放当前页面标题、简短说明和搜索。
- 统计指标放成横向条，不做夸张 hero。
- 卡片只用于项目、题目、痛点等重复条目，不把大页面包成多层卡片。

## 3. Visual Style（视觉风格）

- 主色使用深色侧边栏、浅色内容区。
- 强调色可以使用蓝、绿、琥珀、紫，但不要让页面被单一色系统治。
- 卡片圆角固定为 8px。
- 边框使用轻灰，阴影尽量少用。
- 不使用装饰性渐变球、bokeh、浮夸背景。

## 4. Typography（排版）

- 中文 UI 文案必须正常显示，不允许乱码。
- 标题要短，信息要靠结构承载，不靠大字硬撑。
- 工作台内标题不使用 hero 级字号。
- 正文行高保持 1.55 到 1.75，方便阅读长文档摘要。

## 5. Components（组件）

- 导航按钮使用图标 + 中文文本。
- 状态使用 badge。
- 类型使用 tag。
- 分类切换使用 segmented controls。
- 数字指标使用稳定尺寸的 metric。
- 详情区用 info block 展示证据、误区、行动项。

## 6. Responsive（响应式）

- 桌面端：侧边栏 + 两栏工作区。
- 中等宽度：列表与详情上下排列。
- 手机端：导航、搜索、指标、列表、详情全部单列。
- 文本不能溢出按钮、badge、卡片或表格。

## 7. Forbidden Patterns（禁用做法）

- 不做营销式 hero。
- 不堆叠卡片套卡片。
- 不使用大面积单色渐变。
- 不把说明文字写成使用教程塞进界面。
- 不用“现代、高级、科技感”这类空泛词替代具体 CSS 规则。

## 8. AI Visual Generation（AI 视觉生成）

GPT Image 2 这类图像模型可以用于平台新页面或大改版的视觉探索，但它只负责生成视觉目标，不直接替代真实前端工程。

推荐流程：

```text
读 DESIGN.md
  -> 写页面 inventory
  -> 生成 UI mockup
  -> 实现 React/CSS
  -> 浏览器截图
  -> 对照 mockup 修正
  -> 把稳定规则回写 DESIGN.md
```

使用边界：

- 适合新页面、复杂页面、大改版、多页面视觉一致性校准。
- 不适合普通按钮、文案、表格字段这类小改动。
- 生成图必须服从本文件的布局、密度、颜色、圆角和中文界面规则。
- 真实页面必须经过桌面和移动端截图检查，不能只看生成图。
