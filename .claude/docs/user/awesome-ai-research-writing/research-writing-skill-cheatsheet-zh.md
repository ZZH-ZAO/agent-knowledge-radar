## 怎么用这页

这页不是替代原仓库。
它的作用是让你在真正写论文、改论文、整理实验或准备投稿时，先快速定位：

- 你现在属于什么写作场景
- 更适合直接用 prompt，还是更适合调用 skill
- 在开始之前需要准备哪些输入
- 最终期望拿到什么产物

## 三、如果你常写论文，最值得先会的 5 条

### 1. 从 repo 到初稿

适用：

- 已经有代码、README、实验结果
- 想尽快拉出一版论文骨架

优先用：

- `20-ml-paper-writing`

你至少要准备：

- repo 路径
- 主要实验结果在哪
- 目标会议是什么
- 你认为最核心的贡献句

### 2. 先写中文，再转英文

适用：

- 你脑子里已经有内容，但英文写得慢
- 想先用中文把逻辑理顺

优先用：

- `中转中`
- `中转英`

推荐顺序：

1. 先用 `中转中` 把中文写顺
2. 再用 `中转英` 变成英文论文段落
3. 最后再用英文润色 prompt 做精修

### 3. 写完后做“逻辑检查 + Reviewer 审视”

适用：

- 你担心不是语言问题，而是论证问题

优先用：

- `逻辑检查`
- `论文整体以 Reviewer 视角进行审视`

这一步最适合在：

- 方法节写完后
- 实验节写完后
- 投稿前一轮总检查时

### 4. 去 AI 味不要放在最前面

更合理的顺序通常是：

1. 先把逻辑写对
2. 再把语言写顺
3. 最后再去 AI 味

因为如果前两步没做好，太早 humanize 只会把“逻辑不清的内容”改得更像人写，但不一定更好。

### 5. 图、表、caption 最后不要临时补

更好的做法是：

- 方法确定后就提前规划框架图
- 实验结果出来后同步规划表格结构
- caption 在图表第一次定稿时一起写

这样会比“最后一晚补图补表补说明”稳定很多。

## 四、Prompt 和 Skill 怎么选

### 更适合直接用 Prompt 的情况

- 你只处理一小段文本
- 任务边界非常清楚
- 你不需要改 repo、模板、文件结构
- 你要的是一次性内容加工

典型例子：

- 翻译一段 related work
- 把一段方法写短一点
- 让一段摘要更自然

### 更适合直接用 Skill 的情况

- 任务跨多个文件或多个步骤
- 你需要模板、引用、图表、检查清单等配套流程
- 你希望 AI 能围绕 repo 或论文目录持续工作
- 你希望结果不是一段话，而是一套结构化产物

典型例子：

- 从代码仓库起一篇会议论文
- 把稿件迁移到另一个会议模板
- 按章节协作完成整篇论文
- 处理 Word 文档与修订

## 六、这个案例对你当前工作台最重要的提醒

这份仓库最值得你长期借鉴的，不只是里面有什么 prompt。

更重要的是它做对了三件事：

1. 按真实场景组织资产，而不是按文件类型堆材料
2. 明确说明用户要准备什么输入
3. 明确说明调用之后会得到什么产出

如果你以后继续扩你的工作台知识库，这页速查表本身也可以作为模板继续复用。
