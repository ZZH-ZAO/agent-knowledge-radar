## 计算机网络的主线知识框架

### 1. 分层模型

网络分层不是为了“背五层或七层”，而是为了分离问题。

最核心的主线是：

- 应用层：定义应用语义，如 HTTP、DNS、SMTP
- 传输层：定义端到端通信方式，如 TCP、UDP
- 网络层：定义跨网络寻址与转发，如 IP、ICMP
- 链路层：定义局域网内成帧、寻址与介质访问，如 Ethernet、ARP

知识库中解释这一部分时，应优先回答：

- 每层解决的核心矛盾是什么
- 每层向上提供什么抽象
- 每层向下依赖什么能力
- 为什么现实中大家常说 TCP/IP 四层或五层，而不是死背 OSI 七层

### 2. 从输入 URL 到页面显示

这是计算机网络最值得反复使用的总纲主题。

### 3. HTTP / HTTPS

这一部分不应只停留在“HTTP 明文、HTTPS 加密”。

更重要的是理解：

- HTTP 是应用层语义协议，核心是请求/响应模型
- HTTPS = HTTP + TLS，不是“另一个完全不同的应用协议”
- 缓存、Cookie、状态码、内容协商、长连接、代理、中间缓存都属于应用层语义的一部分
- HTTP/1.1、HTTP/2、HTTP/3 的变化，背后是性能与连接管理方式的变化

推荐分工：

- 《图解 HTTP》负责应用层直觉与常见机制
- 《图解网络-小林coding》负责高频问题串联与 HTTPS 握手讲解
- `RFC` 负责语义边界与版本规范

### 4. TCP / UDP

网络学习中的第一组关键对比是 TCP 与 UDP。

应重点沉淀：

- 面向连接 vs 无连接
- 可靠传输 vs 尽力而为
- 字节流 vs 报文
- 拥塞控制、流量控制、重传、滑动窗口、确认机制
- 什么场景适合 TCP，什么场景适合 UDP

这里特别容易混淆：

- “TCP 可靠”不代表“应用一定成功”
- “UDP 不可靠”不代表“不能在应用层构建可靠性”
- “快”不是 UDP 的全部含义，关键在于语义简单、时延敏感场景更灵活

### 5. IP、MAC、ARP、交换与路由

这一部分是很多人最容易“背过但没真正理解”的区域。

必须讲清：

- IP 地址解决跨网络寻址问题
- MAC 地址解决链路内交付问题
- ARP 负责把目标 IP 映射到下一跳 MAC
- 交换机主要依据 MAC 表转发
- 路由器主要依据路由表转发

重点不是名词定义，而是一个数据包离开发送主机之后：

- 如何确定目标是在本地网段还是远端网段
- 为什么发往远端主机时，二层帧的目标 MAC 往往是默认网关
- 为什么 IP 头里的目标地址不会因为每跳变化而改变，但二层头会变化

### 6. DNS

DNS 常被误以为只是“域名转 IP”，但知识库里应把它沉淀为一套解析体系。

要覆盖：

- 递归查询与迭代查询
- 本地缓存、操作系统缓存、浏览器缓存
- 权威 DNS 与递归解析器
- TTL 的意义
- CDN、智能解析、就近接入与 DNS 的关系

DNS 不负责真正的数据转发，它负责让通信双方找到彼此的网络位置。

### 7. 拥塞控制与流量控制

这是一组必须分开讲的概念。

- 流量控制：协调发送方与接收方速度，防止接收方来不及处理
- 拥塞控制：协调端系统与网络整体负载，防止网络核心过载

推荐沉淀方式：

- 先讲两者分别解决谁和谁之间的矛盾
- 再讲窗口、丢包、RTT、慢启动、拥塞避免等机制
- 最后再解释为什么很多初学者会把它们混在一起

## 常见混淆点

### OSI 七层 vs TCP/IP 分层

- OSI 更适合教学式分层说明
- TCP/IP 更贴近真实互联网协议栈
- 知识库回答时应优先使用 TCP/IP/五层模型解释，再在必要时映射到 OSI

### HTTP vs HTTPS vs TLS

- HTTP 是应用层协议
- TLS 是安全传输层机制
- HTTPS 是在 HTTP 与传输通道之间加入 TLS 后形成的安全访问方案

### DNS 解析 vs 路由转发

- DNS 决定“去哪里”
- 路由决定“怎么到那里”

### MAC 转发 vs IP 路由

- 交换机主要处理二层局域网转发
- 路由器主要处理三层跨网段转发

### 流量控制 vs 拥塞控制

- 前者偏接收端承载能力
- 后者偏网络承载能力

### 教材解释 vs RFC 规范

- 教材负责帮助理解
- `RFC` 负责定义“协议到底算什么”
- 两者冲突时，以规范定义为准，再回到教材补足可理解性
