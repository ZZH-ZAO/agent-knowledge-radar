# 计算机基础知识库总图

## Summary

- Project name: computer-fundamentals
- Project path: `D:\claude-code-sourcemap\.claude\docs\user\computer-fundamentals`
- Document type: user
- Purpose: 说明这套计算机基础知识库为什么要建、按什么结构建、以后怎样持续沉淀书籍和网站资料

## 1. 这套知识库解决什么问题

这不是一套临时八股笔记，而是一套长期知识资产。

它要解决的问题是：

- 资料很多，但分散在书、网站、面经和视频里
- 同一概念在不同材料里表述不同，容易混
- 面试时知道关键词，但不一定能说清楚原理、边界和对比关系
- Agent 即使能回答，也不一定稳定按你的知识框架回答

所以这套知识库的目标是：

> 把计算机基础知识沉淀成“人能系统复习、Agent 能稳定检索”的双层结构。

## 2. 为什么要分 `user` 和 `agent`

`user` 层负责：

- 帮你系统复习
- 讲清楚概念、边界、对比和工程意义
- 适合读书式吸收

`agent` 层负责：

- 给后续 Agent 快速检索
- 压缩成高频概念、常见混淆、速查关系
- 适合在问答、总结、对比时快速调用

## 3. 当前四大主类

这套知识库先按四大类搭骨架：

- 数据结构
- 计算机网络
- 操作系统
- 计算机原理

后续如果你愿意，还可以自然扩展：

- 数据库
- 编译原理
- 分布式系统
- 软件工程基础

## 4. 每一类以后都怎么沉淀

每个大类建议至少有两层内容：

- `analysis.md`
  这一类知识的总图、核心问题、学习顺序、常见考点、易混点
- `analysis-condensed.md`
  给 Agent 用的压缩版，保留高频概念和对比关系

每一类下面再按专题拆分。

例如：

- 数据结构：数组链表、栈队列、树堆、图、哈希、排序、查找
- 计算机网络：分层模型、TCP/UDP、HTTP/HTTPS、DNS、拥塞控制、代理/CDN
- 操作系统：进程线程、调度、同步、内存管理、文件系统、IO
- 计算机原理：指令执行、CPU、流水线、Cache、总线、中断、存储层次

## 5. 以后喂资料时的沉淀规则

无论你给的是书、网站、课程还是面经，建议都按同一个问题框架沉淀：

1. 这个概念是为了解决什么问题
2. 它和相近概念怎么区分
3. 常见考法是什么
4. 工程里常出现在哪
5. 最容易答混的点是什么

这样知识库才不会退化成定义堆砌。

## 6. 当前阶段先做什么

第一阶段先搭骨架，不急着把所有内容填满。

更好的节奏是：

1. 先建总图和目录
2. 再按你投喂的书和网站，一类一类往里沉淀
3. 每沉淀完一块，就补 user 版和 agent 版

## 7. 一句话记忆

这套知识库不是“背八股”，而是把计算机基础整理成一套可复习、可检索、可复用的知识地图。
