# Project Preferences

These preferences should shape future analysis and recommendation work for this repository and related Agent research tasks.
这些偏好会影响以后在这个仓库里做分析、写文档、提建议的方式。

## Writing Style

- Prefer deep, structured explanation over shallow listing.
- 更偏好深、系统、结构化的解释，而不是浅层列点。
- Explain professional terms when they first appear.
- 专业术语首次出现时就解释。
- Write in a lecture or walkthrough style when the topic is complex.
- 复杂主题尽量写成讲稿式、导读式。
- For each mechanism, explain what it is, why it exists, how it is implemented, and what tradeoffs it introduces.
- 对每个机制都解释：是什么、为什么存在、怎么实现、代价是什么。
- Avoid dry bullets that only enumerate modules without interpretation.
- 避免那种只列模块、不做解释的干巴巴 bullet。

## Analysis Style

- Focus on teaching value, not just documentation completeness.
- 更关注“能不能让人学到东西”，而不只是文档齐不齐。
- Compare current design to simpler alternatives.
- 要拿当前设计和更简单的替代方案比较。
- Call out what is actually worth learning for future Agent projects.
- 明确指出哪些点真的值得迁移到未来 Agent 项目。
- Distinguish between core runtime ideas and optional product-layer expansions.
- 区分核心 runtime 思想和可选产品层扩展。
