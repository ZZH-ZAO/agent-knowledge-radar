# Platform（产品化平台）

这里存放可视化知识平台的产品设计文档、路由规划、阅读交互方案和工程逻辑主线。

## 1. 平台路由

当前平台的核心路由是：

- 项目
- 方案
- 痛点
- 工程逻辑
- 资料源
- 面经
- 面试官
- 雷达
- 视觉生成

它们不是普通导航页，而是同一条知识转化链路上的不同阶段。

## 2. 每个路由负责什么

- 项目：看单个样本项目，理解它解决了什么真实工程问题。
- 方案：看多个项目背后的共性方法、成熟做法和可迁移框架。
- 痛点：看 Agent / 大模型行业里的普遍问题、项目证据、数据线索和应对方法。
- 工程逻辑：把项目、方案、痛点和资料源收束成“以后做项目时该怎么一步步做”的决策链路。
- 资料源：统一管理 GitHub、博客、论文和用户输入资料。
- 面经：把知识沉淀转成可学习、可复述、可训练的回答结构。
- 面试官：围绕你的项目和沉淀内容持续追问，训练表达与深度思考。
- 雷达：负责自动发现、候选池、评分和后续沉淀入口。
- 视觉生成：沉淀前端设计控制、GPT Image 2 工作流和页面实现方法。

## 4. 这一层的目标

平台层不是为了单独写产品文档，而是为了回答三件事：

1. 这个知识平台到底服务什么目标。
2. 这些路由之间应该怎样组织，才能真正帮助学习和做项目。
3. 外部资料进入后，如何一步步转成可执行的工程逻辑。
