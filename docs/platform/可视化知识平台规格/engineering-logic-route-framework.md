# 工程逻辑路由总纲

> 目标：把项目、方案、痛点、资料源最后收束成“以后做项目时应该怎么一步步做”的工程逻辑。

## 1. 路由一句话

工程逻辑路由不是重复展示项目或方案，而是回答：

```text
当我以后做一个真实项目时，应该如何把资料学习、问题抽象、设计判断、实现步骤、验证方式和复盘输出串成完整工程链路？
```

## 2. 它为什么要单独存在

当前平台已经有：

- 项目：看样本
- 方案：看通用框架
- 痛点：看行业问题
- 资料源：看外部输入

但你真正需要的不是“知道这些内容”，而是：

```text
我以后自己做项目时，能不能直接拿这套平台指导工程决策？
```

所以必须再抽出一层，把上面几层收束成“做项目的方法”。

## 3. 完整主链路

```text
资料源 / Radar
  -> 优质项目识别
  -> 单项目沉淀
  -> 痛点抽象
  -> 方案形成
  -> 工程逻辑收束
  -> 当前项目行动项
  -> 项目设计 / 实现 / 验证
  -> 面试与复盘表达
```

## 4. 七个阶段

### 4.1 发现阶段

要回答：

- 现在最值得学什么？
- 它属于哪类技术主题？
- 它是不是高质量来源？

输出：

- 候选项目
- 候选资料
- 优先级

### 4.2 沉淀阶段

要回答：

- 这个项目本身到底做了什么？
- 为什么值得学？
- 它解决的核心工程问题是什么？

输出：

- 单项目沉淀
- 可迁移原则
- 项目行动项

### 4.3 抽象阶段

要回答：

- 多个项目背后的共性问题是什么？
- 哪些做法是成熟系统反复采用的？

输出：

- 通用问题定义
- 成熟做法
- 可迁移框架

### 4.4 诊断阶段

要回答：

- 行业内普遍会在哪些地方出问题？
- 哪些项目已经证明这些问题真实存在？
- 常见误区是什么？

输出：

- 行业痛点
- 证据来源
- 数据信号
- 解决思路

### 4.5 决策阶段

要回答：

- 如果我现在要做一个项目，应该先做哪层？
- 最大风险在哪里？
- 哪些能力必须前置？

输出：

- 设计顺序
- 风险边界
- 验证方法
- 默认执行顺序

### 4.6 实施阶段

要回答：

- 具体怎么落地？
- 哪些步骤要写文档？
- 哪些步骤要做验证？

输出：

- 实施路线
- 验证动作
- 文档回写点

### 4.7 表达阶段

要回答：

- 最后怎么复盘？
- 面试官怎么追问？
- 如何讲清楚 trade-off？

输出：

- 推荐回答
- 追问链
- 项目表达素材

## 5. 默认执行顺序

以后做一个真实项目时，默认顺序是：

1. 先看资料源和 Radar，找到最值得学的样本。
2. 看单项目沉淀，理解样本解决的问题和边界。
3. 看方案页，把样本抽象成自己的通用框架。
4. 看痛点页，确认行业里最容易出错的地方。
5. 回到工程逻辑页，决定设计顺序、风险点和验证方式。
6. 进入真实实现，并把过程中发现的新问题回写到平台。

## 6. 风险边界

- 不要一开始就直接做功能实现，先定义问题边界和目标用户。
- 不要只收集项目链接，必须把样本转成方案、痛点和行动项。
- 不要只看 happy path，必须提前定义失败恢复、权限、可观测性和副作用边界。
- 不要把工程逻辑页写成说明书，它必须能指导“下一步做什么”。
- 不要只做内容堆积，任何新增资料都应该检查是否改变当前决策顺序。

## 7. 验证清单

- 我是否知道这轮迭代到底在解决什么问题？
- 我是否能指出参考了哪些项目、方案和痛点？
- 我是否已经明确最大的风险边界在哪里？
- 我是否定义了至少一种验证方式，而不是只停在设计层？
- 我是否把新的判断回写成文档、行动项或面试表达素材？

## 8. 现在最该展示的内容

工程逻辑页应该重点展示：

- 当前平台主链路
- 七个阶段说明
- 每个阶段对应的现有路由
- 当前最重要的痛点
- 当前最重要的方案
- 当前最该优先沉淀的项目
- 做真实项目时的推荐顺序

## 9. 行业痛点研究版补充

工程逻辑页还要服务一个更大的目标：让它不只是概念图，而是能回应 Agent / 大模型工程里反复出现的结构性问题。

这些问题包括：

- 工具结果太大，容易打爆上下文
- MCP / Tool Runtime 接入后，治理复杂度迅速上升
- 多模型 / 多 provider 差异污染 runtime
- 好项目很多，但学习容易停留在笔记层
- 原型容易展示，产品化却很难持续维护

工程逻辑页应该把这些问题收束成可执行判断：

- 该先做什么
- 哪些边界必须先定义
- 哪些验证必须提前做
- 哪些内容要持续回写到平台

## 10. 数据信号

后续可以长期观察：

- 项目到方案的关联率
- 方案到痛点的关联率
- 工程逻辑页引用的文档数
- 当前项目行动项完成率
- 面试表达素材的覆盖率

## 11. 当前项目行动项

- [ ] 给工程逻辑页补上默认执行顺序和风险边界
- [ ] 把项目、方案、痛点、资料源统一映射到工程主链路
- [ ] 为每个真实项目补推荐阅读顺序和验证方法
- [ ] 后续把 block 引用、搜索命中段和版本变化接入工程逻辑页

## 12. 自动进化规则

每次新增项目、方案、痛点或资料源后，都要检查它是否会改变现有工程主链路，并在必要时更新本页。
